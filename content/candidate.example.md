# Candidate Profile

Fill in each line. Delete a line you cannot answer. The models read this file at the start of every session. Keep it short and factual.

- **Role and experience:** e.g. backend engineer, 3 years, building web services and data pipelines.
- **Target level:** e.g. SDE-2 or senior backend.
- **Target company type:** e.g. Series A to C startups, or large product companies.
- **Stacks I know well (use as a bridge):** e.g. Postgres, Kafka, Redis, Kubernetes, and one main language. Name what you run in production. The teacher may compare a new idea to these. The comparison is a bridge, never the main lesson.
- **C++ subset I write in (machine coding):** e.g. C++17 with classes, `std::shared_ptr`, `enum class`, `std::optional`, `std::mutex`. Leave this out to get a plain modern subset.
- **Strengths:** e.g. clean code structure, modular decomposition, pragmatic tradeoffs.
- **Habits to probe:** e.g. skips edge cases, rushes capacity math, goes quiet when stuck.
- **Known weak spots:** e.g. concurrency, consistency models, back-of-envelope numbers.

Do not write your employer, your email address or any internal system name here. The practice sessions are a personal study space, and the models never repeat such names.
